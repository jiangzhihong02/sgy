# 深港跨境拼车撮合小程序 — 设计快照（MVP）

> 与领域词汇（CONTEXT.md）与决策记录（docs/adr/）配套的现状快照。改设计时同步更新本文件与对应 ADR。

## 一句话

微信云开发小程序，帮深港跨境通勤者（现阶段 = 往返香港教育大学 EdUHK 的师生）找到**上车时间相同的队伍**组队拼坐香港的士。**纯撮合**：不预约的士、不经手车费、不负责承运，AA 线下进行。

## 边界（做 / 不做）

- ✅ 组局撮合、局内聊天、签到、信用分、性别自报 + 头像框着色 + 不实举报、管理员代发种子局
- ❌ 预约/叫车、支付与 AA 收款、常设班次（二期）、正式上架（内测后再说）
- ⚠️ 下车点：返校固定目录（终点教大）；离校 = 3 口岸预置 + 任意自定义香港终点（ADR-0009）

## 拼车局状态机

```
创建(招募中) ──T−60 轮询──▶ (可重复) ──T−30 自由退出截止──▶ T−10 关局
    ├─ ≥2 人 ──▶ 成局(已锁定) ──T──▶ 进行中 ──▶ 已完成（信用分入账）
    └─ <2 人 ──▶ 未成局（自动解散，不计爽约）
发起人可在 T−30 前主动 ──▶ 已取消
```

- **成局门槛 2 人**；人数上限默认 4（发起人可设 2–4）。
- **T−60 轮询**：成员 <4 时全员表态"接受当前人数出发？"，T−45 未回复默认接受；因成员进出可在 T−30 前重复发起。
- **T−30**：成员自由退出 / 发起人自由解散的最后时点。
- **T−10**：停止加入、锁定成局判定。
- **T+10**：停止「我到了」签到；之后到局结束仍未签到的成员，由系统自动按爽约结算扣分。
- 约束：**同一用户可并存多个未出发局**：任意两局出发时间差 ≥1 小时；**同方向（返校×返校 / 离校×离校）需 ≥2 小时**（同向需能先完成一趟往返，见 ADR 并发规则）。

## 信用分（轻量，参数可调）

| 事件 | 分值 |
|---|---|
| 初始 | 100 |
| 爽约（T−30 后退出 / 出发后到局结束仍未签到，系统自动记） | −20 |
| 举报坐实：迟到 | −10 |
| 举报坐实：缺勤·没来 / 性别不实（性别不实顺带清空性别） | −20 |
| 到点签到且局完成（结算自动） | +1（封顶 120） |

- 信用 <60 → 暂停发起新局 7 天（仍可加入）。
- 举报：同局 ≥2 名不同成员联名自动坐实，不足 2 人转管理员复核（adminPending / resolveReport）。

## 信任与身份

- 注册：微信手机号验证（开放注册，无需证明 EdUHK 身份）。
- 可选自报性别（微信不提供真实性别）。
- **性别用途**：队伍/聊天里的头像框着色（蓝男·粉女）便于同车辨认；自报不实可由同车成员举报，坐实后清空性别并扣信用分。
- 不展示微信号；联系方式走局内聊天室。

## 页面结构（4 Tab + 子页）

1. **找局**：默认"今天/现在"，可筛方向 + 上车点/下车点 + 还差几人；卡片 = 时间 · 已有几人/上限 · 距发车 · 一键加入。顶栏悬浮"发局"。
2. **聊天室**：我参与的未结束局的队伍聊天（微信式气泡、5 秒轮询、每人每局可发 1 张图——建议群二维码）；局详情内"去聊天室 ›"跳转到此 Tab。
3. **行程（我的局）**：进行中 / 历史；局详情 = 时间线 · 成员（可点开资料 / 标记 / 举报 / 再约）· 规则 · 备注（发起人可改）。
4. **我的**：昵称/性别注册（自报）、信用分与规则、管理员入口。

- 非 Tab 子页：**发局**（create）、**局详情**（ride）、**管理员后台**（admin）。

- 局详情可**转发到微信群**（分享卡片：线路 / 时间 / 已有几人 / 还差几人 / 一键加入）——冷启动传播引擎。
- **管理员代发种子局**入口（作者本人专用）：让内测期列表非空。

## 数据与云函数（以 cloudfunctions/SPEC.md 为唯一契约）

一期集合：`users`（档案+信用）、`routes`（线路目录，seed 7 条）、`rides`（拼车局，**members 内嵌** + 派生 `memberOpenids` 供"一人一局/我的局"查询 + `poll` 轮询内嵌）、`messages`（局内聊天）、`reports`（爽约/上报）。

云函数：`routeInit`（建集合+seed）、`rides`（发/找/加/退/解/签/轮询应答/上报/聊天）、`user`（建档+信用+管理员复核）、`rideSweep`（定时推进状态机与结算）。实现与 action 接口见 `cloudfunctions/SPEC.md`。

> 相对早期草图的偏差：成员关系并入 `rides.members`（不再单独 `ride_members` 集合）、轮询并入 `rides.poll`（不再单独 `poll_responses`），均为减少跨集合一致性负担。

## 通知策略

站内为主（红点 + 打开提醒）；订阅消息仅在拿到匹配模板后"尽力"用于最高价值事件（有人加入 / 出发前提醒）。见 ADR-0008。

## 近期规则更新（2026-09，详见 ADR-0010）

- **游客/注册**：未注册可浏览；注册（填昵称，默认昵称随机不同）后才可 发局/加入/发言/邀请。
- **并发**：不再是"一人一未出发局"；可并存多局，但**出发时间相差 ≥1 小时**才可并存（同方向需 ≥2 小时——同向要先完成一趟往返，2026-09-07 修订，见 ADR-0010 第 9 条）；冲突报错带"已加入 / 新建冲突"对比。
- **结算**：预订后 1 小时关闭进历史。
- **举报**：入口在局详情成员浮层；类型 性别不实/迟到/缺勤（去掉"其他"）；同类同一人只能报一次；≥2 名不同成员联名自动坐实扣分，否则转管理员复核。
- **再约**：已完成局"下周同一时刻"再约（自动复用/新建下周局并发邀请）；受邀者在找局顶部看到邀请条。
- **聊天室**：微信式左右气泡 + 多房间切换 + 5 秒轮询；**局详情内不再内嵌聊天，已加入者点"去聊天室"跳转 Tab**；发图走 **base64 存消息（不用云存储）**，每人每局 1 张，建议用途=发群二维码；成员浮层可见资料/标记"不与其乘车"/改备注（发起人）。
