# 聊天图片改走 base64 存消息，不用云存储（每人每局 1 张）

早期规划（ADR-0010 第 8 条）聊天图片用**云存储 + 临时链接**。内测实跑后发现：

- 云存储需按量付费/开通权限，单人维护想保持零成本；
- 跨账号图片渲染踩过坑（老实现加载 `cloud://` 链接失败，见历史 bug：渲染层网络错误）。

因此改为：发图时前端压缩（q55）→ 读成 **base64 data URI** → 作为 `type:'image'` 消息正文存进数据库（`messages.text`），不落云存储。约束：
- 单条 ≤200,000 字符（≈≤150KB 图）；
- **每人每局只能发 1 张**，UI 建议用途 = 发"微信群二维码"，队友长按保存 → 微信扫一扫进群（绕开平台拉群限制）。

被否决的替代：云存储 fileID + 换临时链接——要开通付费/配置权限，且老实现渲染失败、增加免费档外成本。

后果：DB 消息行更大但数量少（每局 ≤ 成员数张）、图片只存活于数据周期内；**旧版遗留的 `cloud://` fileID 消息不再拉取，前端显示占位"图片（旧版）暂不可见"**。容量参数与发图上限实现唯一来源：`rides/rules.js`（MSG_IMG_MAX）与 `chat.js`。

Status: accepted（ADR-0010 第 8 条图片部分作废）。
