# ADR-0015：签到保持纯自报，不做定位校验

- 状态：已采纳（2026-09-08）
- 关联：ADR-0005（轻量信任模型）、ADR-0002（上车点=口岸的士站）

## 背景

用户提出「点『我到了』时能否用定位确认」：签到（`rides.checkin`）目前是纯自报（置 `checkedInAt`），不加位置概念。评估后发现前置条件不成立。

## 决策

**不引入定位校验。** `checkin` 维持纯自报，继续靠 补签到确认（48h 窗口）+ 队友举报缺勤 兜底。定位相关代码不写。

## 理由 / 取舍

- **主体类目限制（硬约束）**：小程序为**个人主体**。`wx.getLocation` 接口权限与小程序类目绑定，需**企业主体 + 出行/地图等相关类目**，个人主体基本不可用。没有 getLocation，定位确认无从谈起（体验版开发者工具可用模拟定位，但真机不可靠）。
- **即使可用也与信任模型冲突**：口岸过关区 GPS 漂移明显、的士站是具体角落在站内集合位置又不定——硬拦截（距离超阈值拒绝）会误伤"真到了但定位飘了"的成员；这与 ADR-0005 的轻量信任定位不符。
- **现行为已够用**：纯自报 + 事后 48h 补签到确认 + 队友 `absence` 举报（联名/复核坐实扣分），对"谎报到点"的威慑与纠错闭环已存在。

## 后果

- 若未来主体升级为企业且确有防滥用需求，可再评估：`routes` 增加 `lat/lng` 坐标（DESIGN 待办本有"各口岸的士站坐标指引待补"）、`checkin` 可带坐标快照存证（仍建议"展示不拦截"）。
- 本 ADR 记录目的是避免未来重复提出"定位签到"却重走一遍类目调研。
