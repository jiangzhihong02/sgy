# ADR-0018：到场互认用「集合口令」，不引入头像 / 自定义特征

- 状态：已采纳（2026-09-10）
- 关联：ADR-0017（站内聊天永久下线——本 ADR 补上它留下的"见着了怎么认"真空）、ADR-0015（同为"个人主体限制下的取舍"）

## 背景

ADR-0017 下线站内聊天后，成员之间**没有任何站内沟通渠道**，协调改为"到点集合见人"。随即暴露一个真空：

> **陌生人到了同一个的士站，怎么知道谁是自己人？**

当时可用的信号**全部不足**（代码核验）：

- 昵称是系统随机生成（如"拼友3721"）——**在人群里喊不出来**；
- 性别只体现在头像框颜色；
- 「✓ 校内已登记」绿标**要点开某人的资料浮层才看得到**，对"扫一眼人群"无效；
- 集合提示（备注）只到"哪个柱子"的粒度，且是**出发前写的预判**，到了现场常常不准。

## 决策

**给每局生成一个 4 位数字的集合口令**（系统生成、仅同局成员可见），一物两用：

1. **到场互认**——在备注说的位置附近，向疑似队友对一句口令；
2. **快速建群**——成员在微信「**面对面建群**」里输入同一组数字，当场成群（该功能要求参与者就在附近，正好契合"同一的士站、同一时刻"）。

**成员行另有一个结构化信号：「已到 + 时刻」**（如「已到 08:12」，同局成员可见）。签到是**结构化状态**、不是用户产生的文本，故不扩大 UGC 面，也不触碰 ADR-0017 那条线。它与口令分工不同：口令用于**当面确认"你是自己人"**，时刻用于**远远扫一眼"谁到了、还差谁"**。2026-09-10 明确为有意设计——此前它只存在于实现里，规格上是空的。

**明确不采用**：

- **真头像**（识别力最强）——头像是用户上传的**图片**、又要展示给他人，正是 ADR-0017 下线的那条线；
- **自定义"识别特征"文本**（如"我今天穿黑外套"）——是 备注 的同类，属**用户自由文本供他人浏览**，会重新扩大 UGC 面；
- **站内聊天**——已由 ADR-0017 永久排除。

## 理由 / 取舍

- **零 UGC、零隐私接口、零录入成本**：口令是系统生成的数字，用户没有产生任何内容；不需要新增权限申报；也不需要作者先实地录入各口岸的站位表（那个待办至今未做）。
- **一次解决两件事**：它同时给出"**到哪里碰头**"（配合备注）与"**如何确认对方是自己人**"（口令是共享密语）。只做站位标识只能解决前者。
- **建群落在微信里**：平台只显示一个数字，建群动作由用户在微信内自行完成——平台不提供群、不提供聊天，"只做撮合"的边界不被破坏（与 ADR-0017 一致）。
- **责任不压在一个人身上**：发起人默认是**集合召集人**——只是行为约定、不是权限，没有对应的字段或移交动作；他若堵在路上没到，**任何先到的成员点「我到了」即可示意在场**，招呼队友这件事自然落到先到者头上——否则他一个人堵着，整局就散了。

## 后果

- `rides` 增加 `code` 字段（4 位字符串）；发局时生成，并与**同一上车点的活动局避免撞号**（撞了口令会串局）。
- 口令**仅同局成员可见**（`detail` 只对成员返回），不进找局列表。
- 成员行显示「已到 + 时刻」（`detail` 的 `members[].checkedInAt` > 0 时，客户端格式化为 `HH:mm`）——同局成员可见，见上「结构化信号」。
- CONTEXT 的「发起人」多了一层含义：**集合召集人**。
- 仍有一个**无法消除的残余**：口令对不上的人，只能靠"站在备注说的位置 + 时间吻合"互相推断——这是"不做站内沟通"的必然代价，接受。
- 本 ADR 记录目的是：将来若再提"让人认得出彼此"，**先看这里**——头像与自定义特征是**明确排除项**，不要再重新提议一遍。
