# ADR-0016：不做可勾选的"已有人数"预占，改由备注自由表达

- 状态：已采纳（2026-09-09）
- 关联：ADR-0005（轻量信任模型）、ADR-0013（自报不核验）、CONTEXT 备注

## 背景

用户提出：已在线下组好队的发起人发局时应可选"已有人数"（如同行 3 人、只招 1 位补满）。调研后因诈骗风险否决，改为在发局**备注**里用占位符示例引导（"例：已有 3 人同行、再招 1 位拼满"），让用户自己用文字表达。

## 决策

**不做可勾选/可校验的"已有人数"预占字段。** 预组队信息一律走自由文本备注。发起人自己说明"已有几人同行、还招几人"。

## 理由 / 取舍

- **预占人数是不可验证的自报**，与校内身份/性别同为"拿不出证据"的信任盲区（ADR-0013 已承认这类字段的存在）。但校内身份是**威慑/线下辨认**用途；"已有人数"若做成结构化字段，会**被当作可信的队伍状态展示**（卡片上"已有 3 人"的灰人占位），诈骗分子可虚报 3 人实则 1 人来**夸大队伍可信度**、诱人加入——比性别/校内身份更容易被滥用，风险不对等。
- 备注是自由文本，读者天然知道要**自行判断**，不会当成系统核实的硬事实；且发起人确实拉了 3 人时写在备注也能如实传达。
- 代价：找局卡片看不到结构化的"已有几人"，需要点进详情看备注——可接受。

## 后果

- rides 不加预占字段；成局判定、成员展示、签到/结算语义不变（仍只认 app 内真实成员）。
- 若未来真要做，需先解决"如何让同行人数可信"（如让已加入的人各自确认/邀请进 app 成真成员），再谈结构化作。
