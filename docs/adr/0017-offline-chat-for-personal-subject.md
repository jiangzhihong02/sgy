# ADR-0017：下线站内聊天（含图片消息），规避个人主体「社交-笔记」UGC 类目

- 状态：已采纳（2026-09-10）
- 关联：ADR-0011（聊天图片 base64，已被本 ADR 取代）、ADR-0015（个人主体类目硬约束的同类案例）、ADR-0008（内测后合规）
- **作废范围**：本 ADR 取代以下历史条目中关于"站内聊天/图片"的描述——ADR-0003（上车点集合位置"由成员在局聊天室内约定"）、ADR-0004（时间线 T+10 行"未在聊天室说明"）、ADR-0007（"局聊天消息/图片存云数据库/云存储"）、ADR-0010 第 1 条（注册门控动作列举中的 `sendMessage`）与第 8 条（聊天室形态）、ADR-0011（图片 base64）、ADR-0014 代价句（"集合位置由成员在局聊天室内约定"）。这些旧 ADR 正文按惯例不改写，以本条为现行口径；CONTEXT/DESIGN/SPEC/README 已同步更新。

## 背景

正式提审连续被拒。拼车出行类目经申诉后可解释，但**最后一个失败原因是硬性的**：

> 小程序涉及用户自行生成内容（文字、图片）的记录、分享，属**社交-笔记**范畴，为**个人主体小程序未开放类目**。

此前产品在局内提供聊天室（自由文本 + 每人每局 1 张图片，base64 存 `messages`）。审核判定的实体正是这条"成员互发文字/图片、被记录并共享"的链路——即使用户只在同局成员间发、内容已过 `msgSecCheck`，形态上仍是"用户内容记录与分享"，个人主体拿不到该类目。

## 决策

**整个下线"成员互发文字/图片"的链路，不做话术白名单替代**：

- 删除 `rides/chat.js`、`sendMessage` / `rideMessages` / `messages` action、`messages` 集合的读写、客户端「聊天室」Tab 与其页面、局详情「去聊天室」入口、`wx.chooseMedia`（相册/摄像头）——隐私申报随之清零相册/摄像头两项。
- 用户不再有任何"写给别人看的自由文本/图片"入口。用户彼此可见的内容收敛为**功能字段**（备注/自定义上车下车点/昵称/校内身份姓名/反馈——仍是自由文本，继续过 `msgSecCheck`，但它们是结构化业务字段而非内容流，抗性可接受）与**结构化状态**（签到/人数确认/成员列表/绿标）。

## 理由 / 取舍

- **个人主体无解，不是措辞能绕的**：任何"成员可发文字/图片、他人可读"的聊天室都会命中"用户生成内容的记录分享"。截图申诉、换类目都不改变功能形态；改话术（固定句子/纯系统动态）虽去掉了自由文本，仍留一个"消息列表"的形态，且丢了真实协调价值，收益不成比例——**干脆不提供站内沟通**。
- **砍掉的是"站内沟通"，不是撮合价值**：本工具定位是**撮合**（找到同时间同集合点的队伍），不是聊天工具。真实协调通道 = 微信（熟人/线下）。到点集合见人、成员凭 备注（集合点细节）+ 成员列表（昵称/性别色/✓校内绿标）互相辨认；AA 线下当面（「如何 AA」页只留 面对面 / 微信群群收款）。
- **让"内容安全"与"隐私申报"口径一起变干净**：图片没了，`msgSecCheck` 覆盖面只剩短字段；隐私指引不再申报 相册/摄像头/聊天记录。两处官方声明都能如实写"无 UGC 内容流"。
- 替代（被否决）：话术按钮聊天室——形态残留、价值低、仍可能被要求社交类目，不做。

## 后果

- `messages` 集合旧存量不再被任何接口返回；不再写入。集合可留可清（`routeInit` 不再建它）。
- 客户端 Tab 由 4 变 3（找局/行程/我的）；进行中的"我的局"走「行程-未完成」。
- 表达"集合点/车牌/迟到"等动态信息的诉求，由**发起人备注**与既有结构化动作覆盖；迟到的到场确认靠「我到了」签到与补签到确认窗口。
- 若未来主体升级（企业/个体户）且确有站内沟通需要，可重新评估：届时类目开放，本 ADR 不再构成约束（但内容安全与 UGC 声明需同步升级）。
- 本 ADR 记录目的是防止未来把"加回聊天室"当轻量改动直接做，却忘了它是个人主体提审的硬障碍。
