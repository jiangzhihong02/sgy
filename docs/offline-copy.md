# 自用副本（sgy_offline）—— 两个项目的关系与纪律

> 2026-09-10 建立。**本仓库（`sgy`）管线上版；自用副本管另一个仓库 `sgy_offline`。两者从此互不相干。**

## 为什么有两个

| | **主项目（本仓库 `sgy`）** | **自用副本（`sgy_offline`）** |
|---|---|---|
| 用途 | 线上小程序（**已过审**） | 作者自用 / 私下玩 |
| 来源 | 持续开发 | 本仓库 `777c198` 的**纯快照** ＝ **删站内聊天室之前**那版 |
| 主体 / appid | `wx81d8e8ae2b8ff3df` | `wx63a58f0163082859`（另申请） |
| 云环境 | `cloud1-d1gx6bw91f395901c` | `cloud1-d0giflnre1f5a6f54`（另建） |
| 管理员 openid | `oDhfnx…`（旧 appid 下） | `osIpe7H…`（新 appid 下） |
| 站内聊天 | **已永久下线**（ADR-0017） | **保留** |
| 增强编译 | 开 | **关**（`enhance:false`，见下） |

## 三条纪律

1. **别互拷文件**。两份 `cloudfunctions/rides/db.js` 的 `ADMIN_OPENIDS` 必须是**不同值**——`openid` 是**按 appid 生成**的，同一人在两个 appid 下是两个 openid。放一起必然打架。
2. **主仓库的"当前状态"必须是没有聊天室的**。`ADR-0017`、`CONTEXT`、提审申诉口径（`docs/appeal-materials.md`）全都建立在这上面。**别把副本的 `chat.js` / `pages/chat` 拷回来。**
3. **副本不参与提审**。它是个人使用的体验版；带聊天室若提审，会原样撞回「社交-笔记」（见 ADR-0017）。

## 两个已知的"副本专属坑"（都踩过）

- **`enhance: true` + 数组解构 ⇒ 页面白屏**。副本源自 `777c198`，**早于**修复（`2d9b2ef`）。所以副本要么关 `enhance`，要么把那 3 处数组解构照修复改掉。**主仓库已修**，别再照它的写法给副本"统一"回去。
- **管理员的 openid 会变**。换 appid ⇒ 同一个人拿到新 openid ⇒ 旧 `ADMIN_OPENIDS` 匹配不上 ⇒ 「我的」页不出现管理员入口。

## 版本与日志约定

- **版本号两边各自独立**。线上版从 `0.5.0` 起递增（上传时在开发者工具填）；**副本另起一套**（如 `0.1.x`），别再叫 `0.5.0`，免得对照时混。
- **提交信息沿用同一套前缀**：`feat：` / `fix：` / `docs：` / `refactor：`，**一句话说清"改了什么、为什么"**。本仓库的提交历史就是排障档案（例如 `d13888c` 记录了一个循环依赖的成因与修法）。
- **应用内「近期更新」**：`sgy/pages/profile/profile.js` 的 `CHANGELOG` 数组——**发版时手动加一行、最新在最前**（两边各记各的）。
- **重要决策**记 `docs/adr/`（主仓库）；副本的非常规改动记在**它自己的 `README.md`** 顶部那段说明里。
