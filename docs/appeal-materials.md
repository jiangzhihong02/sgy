# 提审反驳口径与材料（个人主体 · 公益拼车组队工具）

> 用途：本小程序为**个人主体**、公益非营利运营。微信审核对本工具会反复给出**两类误判**；本文记录每类的判定依据、为何是误判、**已被审核接受的反驳文案**与配套材料。
> **战绩：2026-09-10 通过审核**（此前两轮分别因「社交-笔记」与「拼车业务」被拒；两轮均以本文口径 + 材料申辩成功）。

---

## 0. 通用提交要点（每次都适用）

- **顺序不能反**：先**重传云函数 `rides`** → 再**重传小程序** → **最后**提交反馈/申诉。
  文案里若写了"本版已删除…"，实物必须对得上；声明与实物不符比不申诉更糟。
- **材料全部出自提交的那一版**；截图含真实姓名/学号一律**打码**，最好用测试数据造。
- **审核有随机性**：同一理由**可能不同结论**（「拼车业务」曾被申辩通过过、之后又出现）。
  ⇒ 每次都**重交文案 + 材料**，不要只写"已整改，请复核"。
- 反馈框**有字数上限**（见过 200 字）⇒ 用下面的短版。

## 1. 误判一：用户自行生成内容（文字、图片）= 社交-笔记

**审核原话（模板）**
> 你的小程序涉及用户自行生成内容（文字、图片、音/视频）的记录、分享，属**社交-笔记**范畴，为个人主体小程序未开放类目，建议申请企业主体小程序。
> 修改指引：你的小程序类目选正确了吗？

**为何会踩上**：本工具曾提供局内**聊天室**（成员互发文字 + 每人每局限 1 张图）。形式上确属"用户内容的记录与分享"，审核据此定性。

**根治（已做，不可回退）**：ADR-0017 整体下线站内聊天——
删「聊天室」Tab 与页面、删 `messages` 集合与 `sendMessage`、删 `wx.chooseMedia`（图片上传）；
隐私申报随之清零"相册/摄像头"。

### 反驳文案（短版，≤200 字，可直接粘贴）

> 本版已删除站内聊天室与图片上传，成员不再互发任何文字/图片，无社区、广场、信息流、评论，不存在内容发布板块。用户填写内容仅为拼车功能字段（昵称、性别、自定义上车/下车点、≤50 字集合备注、校内身份、反馈）；发局页输入均为结构化选项（方向、上车点/下车点、出发时间、人数上限），自由文本仅一处 ≤50 字集合备注，用于告知同车队友集合位置。上述文本已接入微信 msgSecCheck 自动拦截违规。请以本版实际形态为准复核。

**配套材料**
① 底部 Tab 栏（只有 3 个：找局/行程/我的）② 我的 → 关于 → 近期更新（含"取消站内聊天"那行）③ 发局页整页（结构化选项）④ 局详情整页（无聊天区块、无「去聊天室」）

## 2. 误判二：涉及提供拼车业务 = 个人主体未开放类目

**审核原话（模板）**
> 你的小程序涉及提供拼车业务，拼车属个人主体小程序未开放类目，建议申请企业主体小程序。
> 修改指引：个人主体未开放类目修改指引说明（拼车服务）

**为何会踩上**：界面里满是"拼车局 / 的士站 / 组队"，审核按**功能**归类为"经营拼车服务"。

**为何是误判——本工具的真实边界（每条都是事实，不是辩解）**
- **不预约、不派单、不提供车辆**：小程序内没有任何车辆、司机、订单、行程单、计价功能。
- **不经手车费**：无支付、无收款、无金额显示；车费由成员**线下当面**自行分摊。
- **不承担承运**：平台不承运、不提供运输服务。
- **只做信息撮合**：用户发布「某时间、从某口岸上车」的组队信息，他人自由加入；"拼车"（一起拼坐一辆的士）是**成员线下自行发生的行为**。

### 反驳文案（短版，实测 196 字 → 已通过）

> 本工具只做**信息撮合**，不是拼车服务：平台把同一时间、同一上车点的通勤者匹配到一起；"拼车"是成员线下自行发生的行为。平台不安排车辆、不派单、不承运、不经手车费（无支付、无收款、无订单、无计价）。另：本版(0.5.0)已删除站内聊天室与图片上传，无社区/信息流/评论等内容发布板块；用户填写仅为拼车功能字段（昵称、性别、自定义点、≤50字备注、校内身份、反馈）。请以本版实际形态为准复核。

**字数宽裕时（如 300 字）补这句**：
> 发局页输入均为结构化选项（方向、上车点/下车点、出发时间、人数上限），自由文本仅一处 ≤50 字集合备注。

**配套材料**
① 找局列表整屏（卡片只有 时间/线路/人数 → **无金额、无计价、无支付**）② 我的页菜单（只有 信用分/隐私/AA/反馈/关于 → **无订单、无钱包、无支付**）③ 如何 AA 页（页面自带「平台只撮合，不收款…见面当面对付」→ 自证不经手车费）④ 底部 Tab 栏

## 3. 内部一致口径（对审核无效，但对文案必须一致）

`CONTEXT.md`「分层（用词约束）」：**撮合 = 平台的行为；拼车 = 成员的行为**。
对外说明（提审备注、申诉、README、免责声明）**不得**把本工具说成"拼车平台/拼车服务/拼车业务"——那等于替审核按下"拼车业务"的按钮。

> 注意：这条用词规则**不能改变审核的功能定性**（审核看功能、不看词表）。它只是让我们自己的口径**前后一致、经得起追问**。

---

## 4. 若两类都申诉失败怎么办

不是产品形态能解，只剩主体资质：**升级为企业/个体工商户**，类目才对你开放。
（个人主体下，任何"成员互发文字/图片"的形态都会命中社交类目，见 ADR-0017。）
