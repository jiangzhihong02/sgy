# 双账号真机回归清单（内测）

> 目的：每次改了云函数/页面结构后，用**两个真实微信账号**过一遍核心链路，确认撮合行为没被改坏。
> 账号：作者号（管理员，可在开发者工具里当 1 个号用）+ 至少 1 个真人号；要测 3 人联名举报需 3 个号。
> 已知：重构已把 rides 拆成多文件、rideSweep 委托 `rides.__sweep`、线路下拉改拉 DB。本清单覆盖全部被改面。

## 0. 准备（每次代码变动后）
1. 开发者工具重新编译 → 无误。
2. 若改了云函数：右键对应目录「上传并部署：云端安装依赖」。**顺序：先 rides，再 rideSweep。**
3. 若改了页面/要给别人看：上传代码 → MP 后台设为**体验版** → 每个测试号的微信扫体验版二维码打开。
   - 作者号可以直接在开发者工具里操作（登录即作者 openid）；另一号用真机扫体验版。
4. 每个测试号先「我的」→ 点头像 → **注册昵称**（一个填女、一个填男，便于看头像框蓝/粉）。未注册不能参与。
5. 造一条"已完成局"备用（测 举报/再约/历史 用，不用等 1 小时）：
   云开发控制台 → 云函数 `rides` → 云端测试，入参
   ```json
   { "action": "adminSeedDone", "members": ["<账号A的openid>", "<账号B的openid>", "<账号C(管理员/作者)的openid>"] }
   ```
   （openid 在开发者工具里用云函数查一次：console 打印 `cloud.getWXContext().OPENID`，或看现有代码 `rides/db.js` 的 ADMIN_OPENIDS）→ 记下返回的 `rideId`。

## 1. 找局页（回归重点：空态/重试、DB 线路下拉、头像框）
- [ ] 打开「找局」正常出列表（不再是首屏空白）。
- [ ] 断网重开 → 应显示「加载失败 · 自动重试中」，恢复网络后自愈或点「立即重试」。
- [ ] 方向 返校/离校/全部 切换；上车点/下车点下拉选项存在（来自云数据库 routes）；空位筛选用。
- [ ] 列表卡片头像位：有人=彩色字、空位=灰圈＋；已加入/我发起 角标正确。

## 2. 发起 + 加入（回归重点：create/join 全重写）
- [ ] A(发起)发一局：返校、时间 ≥ now+31 分钟、人数上限 4、填备注 → 进详情。
- [ ] 详情顶部备注显示，规则展开文案为中文大白话、无"可被队友标记爽约"。
- [ ] B 在找局页点「加入这一局」→ 成为成员；A 详情出现「去聊天室 ›」。
- [ ] 时间冲突：B 已有此局后——再发起/加入**同方向、出发差 <2 小时**的局 → 弹冲突（提示"同方向需先完成一趟往返"）；已有 返校 后再加 **反方向（离校）且差 ≥1 小时**的局 → 可正常并存。

## 3. 聊天室（回归重点：chat.js 重构、气泡/图片）
- [ ] 底部「聊天室」Tab 有房间；A/B 互发文本：**自己绿色靠右、对方灰靠左，名字/时间在气泡外**。
- [ ] **局详情点「去聊天室」→ 聊天室 Tab 应选中这一局**（不是上次停留的房间、也不是列表第一间）；从 A 局进去再切到 B 局，回头再从 A 局详情进 → 仍回到 A 局。
- [ ] 聊天室切换栏**按出发时间升序**（先出发的在最前）；新加入的局自动插进对的位置，不在末尾；行程页「未完成」同顺序、历史「最近完成在前」。
- [ ] A 发 1 张图（群二维码）→ B 看得到、长按可保存。
- [ ] B（还没发过）也发 1 张图 → **应能成功**（若曾报"图片太大"：已加 q30 二次压缩 + 上限提至 500k，普通截图应能通过）。
- [ ] A 或 B 想发**第 2 张** → 被拒，提示"每人每局最多 1 张"（额度按人，不是全组 1 张）。
- [ ] 未加入者进详情看聊天区 = 只提示"加入后才能查看"，无报错。

## 4. 成员浮层（回归重点：memberInfo/block/complaint）
- [ ] 详情点队友头像 → 浮层显示 名字/性别/信用分；A 标 B「不与其乘车」→ 可取消。
- [ ] **不可见**：A 标 B 后，B 的找局页**看不到 A 发起的局**（等自动刷新/下拉后）。
- [ ] **入队否决（先到者优先）**：A 已在某局（他人发起的也行）→ B 去加入 → 提示"这一队刚好已满员"（托词），B 进不去、不点名。
- [ ] **反向（后到者自主）**：B 先在某他人局 → A（标记者）后加入 → A 能进但收到提示"这局里有你标过的人"；A 详情顶部横幅持续提示，A 可自行退出。
- [ ] 进行中局：A 报 B「性别填写与真实不符」→ "已提交，待复核"（单人不联名）。
- [ ] **性别分级**：第 0 步已完成局内，① 造出 ≥2 人联名报 B 性别不实 → B 性别被清空、可重填（L1）；② 同一 B 累计 ≥2 次坐实（或单局 ≥3 人同报）→ B 性别被反推锁死，B 的「我的」页性别变为"已核实，不可改"；作者可用 adminSetGender（devtools console）解锁/纠正。
- [ ] 已完成局（第 0 步造的）：A 在 B 浮层可报 迟到/缺勤/性别不符，可「下周同一时刻再约 B」→ B 找局页顶部出现"组队邀请"小条，可 去看看/忽略。

## 5. 管理员复核（作者号）
- [ ] 我的 → 管理员后台 → 待复核举报 → 坐实/驳回，信用分相应变化；gender_fake 坐实后目标性别被清空。

## 6. 时间轴（可选，要等约 35–70 分钟；不想等就信任第 0 步 + 手动跑一次 rideSweep）
- [ ] 发局时间设 now+31 分；T−10 前需凑满 ≥2 人锁定成局 → 到点转"进行中"。
- [ ] 双方到点点「我到了」；出发后 10 分钟另一方不能再签。
- [ ] 等结算（上车后 45 分钟，或云控制台手动跑 `rideSweep`）：签到者 +1、未签到仍成员 −20，局转"已完成"。
- 说明：create 强制 boardAt ≥ now+30 分，故全真时间轴成本高；建议平时用 adminSeedDone 覆盖 done 态，时间轴抽空验证一次即可。
